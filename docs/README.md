# OctoAcme Project Management — Docs Overview

This folder contains OctoAcme's process documentation for managing projects from initiation through retrospective. Use these docs as a reference for how we work, or as context for Copilot Spaces.

---

## Process at a Glance

OctoAcme follows an iterative, customer-first delivery model. Projects move through five stages:

| Stage | Summary |
|---|---|
| **Initiation** | Validate the idea, align stakeholders, produce a one-pager, and get a go/no-go decision. |
| **Planning** | Break work into a prioritized backlog, define the release plan, and capture risks and dependencies. |
| **Execution** | Build and test in short iterations, track progress on the project board, and escalate blockers promptly. |
| **Release** | Deploy through the standard pipeline, run smoke tests, verify, and announce to stakeholders. |
| **Retrospective** | Capture what went well and what to improve; convert action items into backlog issues. |

---

## Key Roles

| Role | Focus |
|---|---|
| **Project Manager (PM)** | Delivery coordination, schedules, risks, and status reporting |
| **Product Manager (PdM)** | Outcomes, backlog prioritization, and success metrics |
| **Developers** | Implementation, testing, code review, and technical risk identification |
| **QA / Testing** | Quality validation and acceptance criteria sign-off |
| **Stakeholders** | Input, approvals, and business alignment |

---

## Communication Cadence

- **Twice-weekly standups** — progress, blockers, dependencies
- **Weekly PM + PdM sync** — status, risks, decisions
- **Monthly stakeholder updates** — milestone progress and roadmap alignment
- **Sprint/milestone demos** — delivery team shows working increments
